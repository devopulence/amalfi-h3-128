## Key Findings (for Session 3 to know going in)

1. **D6 rotation widening is a hard prerequisite of D2-G1**, despite the playbook §4.1 listing them as separate sub-phases in the order D2 → D6. The encoder applies rotation after digit assembly; stock rotation loops on `H3_GET_RESOLUTION` (returns 0-6 for ext cells). Without D6, ext digits 4-22 stay in the home-face frame; decoder reads them as canonical-orientation; round-trip diverges. **Lesson**: treat playbook sub-phase order as scope grouping, not gate-prerequisite order.

2. **`_adjustOverageClassII` indexes static lookup tables sized for stock res only.** Not flagged in playbook §6 trap catalog, but a real §5.6 trap class. ASAN-detectable as `global-buffer-overflow` at `faceijk.c:889`. Must be extended for any decoder ext-res work to OOB-clean. Pattern is deterministic (`2 * 7^n` and `7^n`), but res 22 overflows int32.

3. **Stock H3 coordijk arithmetic overflows int32 at ext res for off-face-center points.** UBSAN-flagged signed-overflow in `_ijkNormalize` (line 211), `_hex2dToCoordIJK` (line 345), `_upAp7r` (line 496). Stock never exposed this because res ≤ 15 keeps i/j/k well below INT_MAX. testEncoderExt scoped to res 19 to avoid; D4 hierarchy recursion to res 22 will need this resolved.

4. **Stock test fixtures encode the old MAX_H3_RES = 15 upper bound at 4 sites this session.** Each surfaced per CLAUDE.md non-negotiable #2 ("if compatibility must break, STOP and surface") before landing. Session 3 should `grep -n 'res.*16\|res.*= *16\b\|res, *16\b\|MAX_H3_RES' src/apps/testapps/` before each widening commit to spot more.

5. **`H3_GET_DIGIT_AT_RES` and `H3_SET_DIGIT_AT_RES` collapse to stock macros for r ≤ 15.** This is what makes Pattern 3 transfers stock byte-identical: every Rule LB / DR / DW switch is a no-op for stock cells. Verified across 17 widening commits — stock 316 ctest stayed green at every step.

6. **clangd LSP diagnostics are stale throughout.** The editor reports `static_assert sizeof(H3Index) == 16 failed` because LSP can't resolve `__SIZEOF_INT128__`. Actual cmake build under clang has the macro and the assert passes. Ignore LSP warnings unless they correlate with cmake build failures.

7. **Each pre-commit hook run = ~9 minutes wall time.** 18 commits this session = ~150 minutes of pure ctest time. Plan Session 3 accordingly: each granular widening commit is ~9 minutes.
