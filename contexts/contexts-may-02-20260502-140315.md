## Key Findings

- **Stock parent → ext child requires explicit ext-sentinel population.** A stock H3Index has high half = 0 by construction. When `_iterInitParent` extends it to an ext child resolution, simply zeroing digits `parent_res+1..child_res` leaves digits `child_res+1..22` at 0 — which makes the cell non-canonical (must be 7 for `isValidCell`). The fix populates sentinels through digit 22 whenever `child_res >= 16`. POC-3 IT-15 caught this on first run.
- **`-Werror=unused-function` fires on `static inline` helpers that are never called.** POC-2's first compile failed because two debug helpers (`high64`, `low64`) were defined but never used. Removing them was the right fix; `(void)foo` suppression would have been a worse pattern.
- **Integer-valued doubles are useless for testing input variation.** POC-4's ABI-22 originally fed `(double)i` and `(double)(i*2)` — IEEE-754 representations of 0.0..7.0 differ only in their exponent fields, and the shim's hash extracted only the low 45 mantissa bits (which were all zero). Result: all 8 "distinct" cells were bit-identical. Fix: use non-integer doubles like `40.7128 + i*0.001`.
- **`gcc` on macOS resolves to Apple clang.** All four POCs were built with `Apple clang version 21.0.0`. The CLAUDE.md prompt says `gcc` but the toolchain is clang — `__SIZEOF_INT128__` and `__uint128_t` are both supported by clang, so the compiler gate works either way.
- **`__builtin_clzll(0)` is UB.** POC-2 explicitly tests `_firstOneIndex(0) == -1`. The fix is the standard high/low half split: only call `__builtin_clzll` on a non-zero word.
- **The 823,543-child full-depth enumeration runs in well under 2 seconds on arm64.** Took roughly 600ms wall in this session, well within the 1–2 second budget noted in poc3.md.
