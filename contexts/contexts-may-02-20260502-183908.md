## Key Findings (for Session 2 to know going in)

1. **POC-1 in isolation passing was the right diagnostic when stock tests went red.** When Phase A.2 first turned ctest red, running `gcc -std=c99 ... poc1_bit_layout.c -lm && ./poc1` confirmed the macros were correct (685/685) and pointed at the integration: stock predicates in `h3Index.c`. The bit-magic window-clearing trick (`<<= shift; >>= shift`) naturally bounded at 64 bits in stock code; under `__uint128_t` it expands to 128 bits and pulls in inverted high-half garbage. This is the playbook §6.4 / §6.5 trap class — Phase E territory, but a Phase A.2 blocker for stock byte-identity. Fix: cast h to `(uint64_t)` before the bit-magic. Two predicates (`_hasAll7AfterRes`, `_hasDeletedSubsequence`).

2. **Stock Group A masks must be retyped from `(uint64_t)` to `(H3Index)`.** Otherwise `~MASK` is a uint64 value that zero-extends to `__uint128_t` when `&`'d with `H3Index`, clobbering the high half on every SET macro. The mask bit positions are unchanged; only the C type widens. This is a strict requirement of typedef widening, not an "improvement," and POC-1's Group B used this pattern — but the playbook didn't explicitly call it out as a Phase A action item. Surprise during integration.

3. **CLI app `H3Index` decls passed to the args framework's sscanf must be zero-initialized.** sscanf with `%PRIx64` writes only 8 bytes to the address. The high 8 bytes of an uninitialized `__uint128_t` are stack garbage. `cellToParent` faithfully passes that garbage through to `*out`, then `originParent == destinationParent` returns false even when their low halves match. Three sites in `h3.c` (`intToString`, `areNeighborCells`, `cellsToDirectedEdge`) had to be `= 0`-initialized. The existing `DEFINE_INDEX_ARG` / `DEFINE_CELL_ARG` macros already zero-init.

4. **`fgets` includes the trailing newline.** New strict-hex `stringToH3` initially rejected stock test fixture lines because `\n` isn't a hex digit. Fixed with a trailing-whitespace strip before validation. Stock test fixtures pass cell strings via `fgets` with the newline still attached; the old `sscanf("%PRIx64", ...)` path stopped at the first non-hex char, hiding this dependency.

5. **macOS Xcode 16+ SDK marks `sprintf` as `__deprecated_msg`.** Phase A required `-Wno-error=deprecated-declarations` to keep stock building. Phase C rewrote `h3ToString` to `snprintf` so this flag is no longer strictly required but is kept as defensive cushion.

6. **"One widening site = one commit" granularity is aspirational, not literal, for Phase A.** Typedef widening alone won't compile (Group A masks need H3Index typing); mask retyping alone is a no-op (typedef hasn't changed); Group C macros need `__uint128_t`. They form an interdependent unit. The cascade fixes (CLI app `printf`s, sscanf zero-init, stock predicate uint64-restrictions) are part of "the typedef change cascades through every header" per playbook §4.2 — also unavoidable in the same commit. Phase A landed as: A.1 (MAX_H3_EXT_RES alone, self-contained) + A.2 (everything else, single coherent commit).

7. **CTest run time under sanitizers is ~516 seconds (8.6 minutes).** This is unavoidable cost of `-fsanitize=address,undefined -O1`. Pre-commit hook waits for the full run. For Session 2, plan accordingly — each granular widening commit costs ~9 minutes of build+test wall time.
