## Key Findings (for Session 3 continuation)

1. **iterStepChild needs the explicit top-guard** even though stock H3 doesn't have it explicitly. Stock's for-loop happens to handle the childRes == parentRes case via the `if (i == _parentRes)` early-return on iter 1. Switching to a while-loop loses that implicit guard. POC-3 line 236-240 is the explicit version. Lesson: when porting POC patterns, port the *whole* control flow — implicit invariants don't survive structural changes.

2. **`_hasChildAtRes` and `cellToCenterChild` must be widened together.** Splitting them breaks `cellToCenterChild`'s output (creates a half-state cell that looks like a stock res-0 base cell). Polyfill — even though it's post-MVP and stock-only — propagates that malformed cell through `nextCell` and cycles. The fix is to bundle both into one commit; polyfill itself stays untouched.

3. **D4-G6 (823,543-child enumeration at res 22) is achievable today** despite the Session 2 coordijk deferral. cellToChildren is purely digit manipulation — no coordijk involved. Build the parent via setH3Index (Phase D1, no coordijk) and walk children digit-only.

5. **isResClassIII works as-is for ext cells** (parity preserved because 16 is even). F4 gate is automatic — verify in the F-suite test, no widening needed.
