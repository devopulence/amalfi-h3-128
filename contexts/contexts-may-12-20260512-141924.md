### Architectural notes

1. **cffi ABI mode wheels should NEVER carry a CPython ABI tag.** Setuptools auto-tags wheels with the build host's `cp{major}{minor}-cp{major}{minor}-{plat}` by default, even when no C extension is built. For pure-cffi packages the correct tag is `py3-none-{plat}` — the `none` ABI says "no Python ABI requirement," and `py3` says "any Python 3.x." The mechanism that lets you control this is overriding `bdist_wheel.get_tag()`. Trying to control it via `has_ext_modules()` alone is unreliable across setuptools versions. **Save this for any future cffi-ABI-mode Python package in the platform.**

2. **`v0.3.0-python-bindings` tag stays valid.** v0.3.1 is purely additive — the wheel becomes MORE permissive (any Python 3.x with cffi, not just 3.11). Existing consumers continue to work. No backward-compatibility break. The retag is a strictly safer release.

3. **macOS CI now produces `universal2` not `arm64`.** Earlier wheels were tagged `macosx_26_0_arm64` (local macOS 26 build). CI's macos-latest runner is macOS 15 currently, and its lipo'd universal2 binary tags `macosx_15_0_universal2` — works on both arm64 and Intel Macs. Slight expansion of compatibility surface.

4. **`.env` was never compromised in git history.** The PAT exposure is conversation-level only (system reminder echo). Threat model is "anyone with access to the conversation transcript." The user accepted this risk. The new `.gitignore` entry closes off the only avenue by which a future careless `git add -A` could commit it.

5. **Repo discipline relaxed where it was over-cautious.** Sessions 1-7 left context files and certain `.claude/` content untracked under the principle "session-state is ephemeral." On reflection, the older context saves are valuable historical record (~30 KiB each, audit-trail-grade documentation of how the work happened). Now tracked. The principle that survives intact: **never `git add -A`, only named-file staging** — that's what kept `.env` safe through five days of working alongside it.

They had no business in the H3 fork's `.claude/` tree. Removing them keeps the fork focused on H3.
